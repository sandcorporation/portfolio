# 개발 팁 작성 지침

개발 팁(/tips)은 프로젝트와 상관없이 다시 쓸 수 있는 짧은 요령이다. 긴 사례 글은 블로그 「기록」에 쓰고, 여기에는 한 가지 요령만 쓴다. 본문은 블록 문서가 아니라 마크다운 하나(`body`)다.

## 1. 무엇을 쓰나

- 팁 하나에 요령 하나. 다음 순서로 3~6문단을 쓴다: 문제(무엇이 어떻게 보였나) → 원인 → 해법 → 짧은 코드 예시.
- 소제목이 필요하면 ### 를 쓴다(제목은 페이지가 따로 그린다).
- 코드 예시는 펜스 코드 블록에 언어 이름을 붙인다(python, typescript, javascript, bash, sql, json, yaml 등). 언어를 붙여야 색이 입혀진다. 예시는 핵심 몇 줄로 줄인다.
- `title`은 요령을 한 줄로 말한다(「~하면 ~된다」, 「~할 때는 ~」). `summary`는 목록 카드에 보이는 한 줄이다.
- `categories`는 이 도구가 함께 돌려주는 `categories`의 값(value) 가운데 1~2개를 고른다. 목록에 없는 분류는 쓸 수 없다.

## 2. 공개 금지 (가장 중요)

- 출처를 쓰지 않는다. 팁이 나온 내부 사건 기록, 이슈·티켓 번호, 회의, 작업 로그를 본문에 옮기지 않는다. 팁에는 출처 필드가 없다.
- 내부 서버·호스트·도메인 이름, IP(사설 IP 포함), 포트, 비밀값, 토큰, 개인 경로를 쓰지 않는다. 예시가 필요하면 example 같은 일반 이름을 쓴다.
- 실제 사람 이름, 계정, 고객 이름을 쓰지 않는다.

## 3. 발행

- 초안으로 만들고(`create_tip`), 고칠 때는 `update_tip`을 쓴다.
- 초안은 `issue_tip_preview_url`로 낸 미리보기 링크로 먼저 보여 주고, 사람이 확인한 뒤 `publish_tip`한다.
- 내릴 때는 `unpublish_tip`(초안으로 되돌림), 아주 지울 때만 `delete_tip`을 쓴다.
