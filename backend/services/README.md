# services — 도메인 서비스 계층

제안서·리비전·접근 코드·포트폴리오·문의 같은 도메인 규칙은 이 아래 모듈에 둔다.
ninja API(`core/api.py`와 이후 앱의 api)와 MCP 도구는 **같은 서비스 함수**를 부른다.
엔드포인트·도구는 입력 검증과 응답 모양만 맡고, 규칙은 여기서만 정한다.

- 외부 의존(객체 저장소·Discord·PDF 렌더러)은 함수 인자나 `adapters/`의 등록 지점을 통해 받는다.
- 블록 문서의 스키마·검증은 `documents/`(순수 Pydantic, Django 무관)에 있고, 서비스와 모델이 `validate_document`를 부른다.
- 예: `home.py`는 사이트 프로필에서 홈 셸에 심을 데이터(`HomeData`)를 만든다.
- 예: `portfolio.py`는 포트폴리오 항목을 읽는다. 공개 조회(`public_cards`·`public_detail`·`public_slugs`)와 숨긴 항목까지 보는 전체 조회(`all_items`·`get_item`)를 나눠 두었다. 제안서 `case-ref`와 MCP 도구는 전체 조회를 쓴다.
- 예: `media.py`는 미디어(Object Storage의 파일)를 다룬다. `start_upload`(presigned PUT) → `complete_upload`, 서버가 바이트를 가진 경우의 `upload`, `list_media`, `public_url`, `delete_media`(발행 리비전·공개 페이지가 쓰는 미디어는 `MediaInUse`로 거부; `usage_of`가 사용처를 모은다), 서빙할 때 미디어 참조(gallery·audio-compare·video)의 URL을 채우는 `resolve_document`(`private=True`면 비공개 미디어에 10분짜리 presigned URL), 제안서 페이지가 만료된 URL을 다시 받을 때 쓰는 `document_media_url`. 비공개 미디어는 제안서 문서에서만 참조할 수 있다. 완료되지 않은 미디어는 블록·대표 이미지에서 참조할 수 없다(`content.models.stored_document`가 저장 때 검사).
- 예: `portfolio.py`의 쓰기 함수(`create_item`·`update_item`·`set_visibility`·`reorder`·`list_summaries`·`read_item`)와 `profile.py`(`get_profile`·`update_profile`)는 입력을 Pydantic 모델(`NewItem`·`ItemPatch`·`ProfilePatch`; 주어진 필드만 바뀜)로 받고 Pydantic 모델을 돌려준다. 거부는 `errors.py`의 `Rejected`(블록 경로 목록, 저장 안 됨)·`NotFound`·`Conflict`. MCP 도구(`mcpserver/tools.py`)는 이를 `isError` 결과로, 관리자 API(`core/admin_api.py`, `/api/admin/...`)는 404·409·422로 바꾼다.
- 예: `proposals.py`는 고객·제안서(초안)를 다룬다. 고객 `list_clients`·`create_client`·`update_client`, 제안서 `list_proposals`·`get_proposal`·`create_proposal`(두 탭 「견적 제안」「회사소개·수행사례」로 시작, 무작위 slug)·`duplicate_proposal`·`update_proposal`(메타), 문서 `replace_document`·`replace_block`·`insert_block`·`delete_block`·`add_tab`·`delete_tab`·`rename_tab`·`reorder_tabs`(블록은 `block_id`, 탭은 `tab_id`로 가리키고 다른 곳은 건드리지 않음; 초안은 발행 뒤에도 고칠 수 있고 회수된 제안서만 `Conflict`, 오류 경로는 `document.tabs[..]`), 미리보기 `issue_preview_url`(서명·`PROPOSAL_PREVIEW_MAX_AGE` 30분)·`proposal_for_preview`, 화면 데이터 `page_data`(초안 미리보기)·`revision_page_data`(고객 화면, 리비전 스냅샷)·`CodeScreenData`·`ExpiredScreenData`.
- 예: `publishing.py`는 발행을 다룬다. `publish(slug, access_code=None) -> Published`(초안을 다음 리비전 v1, v2…으로 얼려 저장, 문서번호 `SC-{서울 날짜 YYYYMMDD}-{고객코드}-{고객별 일련번호 3자리}`, 첫 발행 때만 `access_code` 평문), `reissue_access_code(slug, access_code=None) -> IssuedCode`(새 코드 — 직접 정한 값이면 그것, 비면 자동 8자; 기존 고객 세션 전부 무효), `revoke(slug)`(되돌릴 수 없음; 다시 발행·편집 불가, 복제해서 새 주소로), `list_revisions`·`get_revision(slug, number)`, `latest_revision`·`is_expired`·`code_matches`. 리비전(`ProposalRevision`)은 저장 시점 문서·메타를 담고 바뀌지 않는다(미디어 URL은 서빙 때 채움). `snapshot_document`는 #13이 `case-ref`를 펼칠 자리. 동시 발행은 제안서 → 고객 행 순서의 `select_for_update`로 줄 세우고, `(client, serial)` 유일 제약이 뒤를 받친다. 접근 코드는 Django 비밀번호 해셔로만 저장된다.
- 예: `proposal_access.py`는 고객이 `/p/<slug>`에 들어오는 길이다. 세션은 제안서 전용 서명 쿠키(`proposal_<slug>`, Path `/p/<slug>`, HttpOnly·Secure·Lax, `PROPOSAL_SESSION_MAX_AGE` 7일; 값은 코드 발급 시각이라 재발급하면 무효) — `has_customer_session(request, proposal)`·`start_customer_session`·`end_customer_session`. 코드 확인 `try_code(proposal, code, ip) -> Attempt`(제안서+IP별 오입력 `PROPOSAL_CODE_MAX_FAILURES`=5회면 `PROPOSAL_CODE_BLOCK_SECONDS`=15분 차단, 차단 중엔 맞는 코드도 거부, `django_cache`). `try_code(…, user_agent)`는 성공·실패·차단 시작을 이벤트로 남긴다. 알림 훅: `on_blocked(proposal, ip)`(차단이 시작될 때 한 번)·`on_pdf_downloaded(proposal, revision)`(PDF를 받을 때) — Discord로 보낸다.
- 예: `proposal_events.py`(#18)는 고객 행동 기록과 주인 알림이다. 이벤트(`ProposalEvent`): 코드 성공·실패·차단 시작·열람·탭 전환·PDF, 시각·리비전·IP·User-Agent(255자). 열람 = 세션 있는 고객의 페이지 로드이고, 같은 리비전·IP·UA의 30분 안 재방문은 하나(`VIEW_DEDUPE_SECONDS`). 리비전별 첫 열람 알림은 `first=True` 이벤트(리비전당 부분 유일 제약)가 한 번만 만든다. 알림 실패·예외는 고객 요청을 막지 않는다. `record_view`·`record`·`tab_allowed`(탭 보고 제한), 조회 `list_events(slug, limit=200) -> list[EventOut]`(시간 순; #24 MCP 도구용, 없으면 `NotFound`). 미리보기·인쇄 경로는 부르지 않는다. 탭 전환은 `POST /p/<slug>/tab`(세션·CSRF 필요).
- 예: `pdf.py`는 리비전 PDF를 다룬다. `publish`가 같은 트랜잭션에서 `enqueue`(리비전당 `PdfJob` 하나). 워커(`manage.py pdf_worker`, compose `worker`)는 `work_once` = `claim_next`(`SKIP LOCKED`로 다음 할 일을 잡고 `locked_at`; `PDF_JOB_STALE_SECONDS`보다 오래 「처리 중」인 작업은 죽은 워커 것으로 보고 회수) → `run`(렌더러가 `PDF_PRINT_BASE_URL`+`issue_print_url` 인쇄 → 비공개 버킷 `pdf/<문서번호>.pdf` → 완료). 실패는 1·2분 뒤 자동 재시도, `PDF_JOB_MAX_ATTEMPTS`(3)번째면 실패로 남고 `retry(revision)`(admin 「PDF 다시 만들기」)로 처음부터. 상태 조회 `pdf_status(slug, number=None) -> PdfStatus`(#24 MCP 도구용), 고객 다운로드 `ready_job`·`download_url`(10분 presigned, 파일명 `<문서번호>.pdf`).
- 예: `blocks.py`는 블록 타입 목록(`block_types`), 타입별 JSON Schema와 예시(`block_schema`), 문서 전체 스키마(`document_schema`)를 낸다. MCP `block_schema` 도구가 쓴다. 새 블록 타입은 `EXAMPLES`에 예시를 더해야 시험이 통과한다.
- 예: `blog.py`(#74)는 블로그 「기록」(/blog)의 글(`BlogPost`, 블록 문서)을 다룬다. 주인 쪽(MCP `mcpserver/tools_blog.py`): `list_posts(published_only=True, limit=None, tag="")`(발행순 내림차순, `published_only=False`면 초안이 먼저)·`get_post(slug, published_only=True)`·`create_post(NewPost)`(slug를 비우면 제목의 라틴 글자로, 3자 미만이면 `post-<hex6>`, 겹치면 `-2`·`-3`; 직접 준 slug가 겹치면 `Conflict`)·`update_post(slug, PostPatch)`(메타·문서 통째, slug는 그대로)·블록 단위 `replace_block`/`insert_block`(탭 생략 시 첫 탭)/`delete_block`·`publish_post`/`unpublish_post`·`delete_post`. 블록 편집은 제안서와 같은 `document_edit.py`(문서를 그 자리에서 고치고 `NotFound`)를 쓴 뒤 문서 전체를 다시 검증한다(거부는 `Rejected`, 경로 `body.tabs[..]`). `published_at`은 처음 발행할 때 모델 `save`가 채우고 그 뒤 유지(다시 발행해도 그대로, admin에서 고칠 수 있음). 공개 쪽(#75 화면·셸): `public_cards(limit, tag)`·`public_detail(slug)`(이웃 글 `prev`=더 오래된 글, `next`=더 새 글)·`public_slugs`·`public_tags`·`feed_items`(RSS). 초안은 공개 쪽 어디에도 나오지 않는다. `home.py`의 `recent_posts()`가 홈의 최근 글 3건이다. 글이 쓰는 미디어는 `media.usage_of`가 센다(발행 글은 「pages」, 초안은 「drafts」).
- 예: `inquiries.py`는 문의를 다룬다. `submit(NewInquiry, trusted=, ip=)`(저장 → Discord 알림; 알림 실패는 접수를 막지 않음. `trusted`는 엔드포인트가 공유 시크릿으로 정함 — 믿는 호출자만 `site`를 정하고 honeypot·IP 제한(`INQUIRY_RATE_LIMIT`/시간, `django_cache`)을 건너뜀; honeypot에 걸리면 `Received(None)`), `list_inquiries(unhandled_only=, limit=)`·`mark_handled(id)`(멱등; #24 MCP 도구용). 제한 초과는 `errors.RateLimited`(HTTP 429).

MCP 도구(`mcpserver/tools.py`; 도메인별로 `tools_media.py`·`tools_proposals.py`·`tools_publishing.py`, `protocol.py`가 불러 등록)는 `@tool(이름, 제목, 설명, 입력 모델)`로 등록하는 얇은 껍데기다. 도구 하나가 서비스 함수 하나(`one`/`many`가 거부를 `isError`로 바꿈). 접근 코드는 `publish`·`reissue_access_code` 응답에만 나온다. 제안서 작성 지침은 `proposal_guide`(지침 마크다운 `mcpserver/proposal_guide.md` + 권장 골격 `PROPOSAL_SKELETON`)가 내리고, INSTRUCTIONS와 작성 도구 설명이 먼저 읽으라고 안내한다. `pdf.retry_revision(slug, number)`는 `retry`의 slug 판이다. `/mcp`(Streamable HTTP, JSON 응답만, 스코프 `admin`)와 ninja 관리 API(`auth=BearerAuth("admin")`)는 같은 sandcorp-auth 토큰 검증(`oauth/bearer.py`)을 쓴다.
- `home.py`: `ceo_intro`는 홈에 그리지 않는다(필드만 유지, 셸 데이터에 싣지 않음; #92).
